# 异常处理

> 一句话：**用 `try` 包住可能出错的代码，用 `except` 接住错误**——别让一个小错把整个程序搞崩。

## 1. 核心语法结构（四件套）

```python
try:
    # 可能出错的代码（只放真正危险的那几行）
    pass
except SomeError:
    # 出错时怎么办
    pass
except AnotherError:
    # 多个 except：捕获不同类型的错误
    pass
else:
    # 没出错才执行
    pass
finally:
    # 不管出不出错，都要执行（常用于关闭文件、释放资源）
    pass
```

**顺序是固定的**：`try` → `except`（多个）→ `else` → `finally`。
`else` 和 `finally` 都是可选的，但写的话只能按这个顺序。

## 2. 简单例子

```python
try:
    age = int(input("输入年龄："))
except ValueError:
    print("请输入数字")
else:
    print(f"年龄是 {age}")
finally:
    print("程序结束")
```

## 3. ⚠️ 多个 except 的顺序（铁律）

> **写多个 `except` 时，必须"子类在前，父类在后"**，否则父类会把子类全吃掉。

```python
try:
    ...
except ValueError:        # ✅ 更具体（子类）在前
    print("值的类型不对")
except Exception:         # ✅ 兜底（父类）在后
    print("其他错误")
```

写反了（`except Exception` 在前），后面那个 `except ValueError` 永远执行不到。

## 4. 主动"扔错"：`raise`

| 项 | 说明 |
| --- | --- |
| 作用 | 当参数不合法、业务不满足时，**主动**抛错 |
| 写法 | `raise ValueError("年龄不能为负")` |
| 好处 | 比"返回 None"清晰一万倍——调用方知道是参数错了，而不是没数据 |
| 异常链 | `raise 业务异常("消息") from e`（保留底层的原始错误，方便排查） |

```python
def set_age(age):
    if age < 0:
        raise ValueError(f"年龄不能为负：{age}")
    return age
```

**异常链**：

```python
try:
    data = json.loads(text)
except json.JSONDecodeError as e:
    raise ValueError("配置解析失败") from e     # 保留原始错误
```

## 5. 自定义异常类

```python
class MyError(Exception):        # 必须继承 Exception
    pass
```

**怎么写**：

```python
class ConfigError(Exception):
    """配置错误"""
    pass

raise ConfigError("配置文件缺少 database 段")
```

> **关键**：在 Python 里，所有想用 `raise` 抛出的异常，**必须继承自 `Exception` 这个"老祖宗"**。
> 如果不继承它，Python 不认这个异常，`raise` 的时候会直接报错。

**为什么自定义**：

1. 和内置异常区分开，不会"串错类型"
2. 可以搭继承体系：父类抓全局，子类抓细节
3. 能带额外属性（如 `err.user_id`、`err.code`）

## 6. 必背"报错名"清单（最常见的 8 个）

| 异常名 | 触发场景（大白话） |
| --- | --- |
| `ValueError` | 类型对了但值不对（如 `int("abc")`） |
| `TypeError` | 类型不对（如 `"字符串" + 1`） |
| `KeyError` | 字典里找不到这个键 |
| `IndexError` | 列表越界（只有 3 个，非要拿第 4 个） |
| `AttributeError` | 对象没这个属性（如 `"abc".foo`） |
| `FileNotFoundError` | 找不到文件（路径写错了） |
| `ZeroDivisionError` | 除数是 0 |
| `Exception` | 万能兜底（不知道具体，就用它兜底） |

> 📌 冷知识：`KeyboardInterrupt`（Ctrl+C）和 `SystemExit` **不继承 `Exception`**，
> 所以 `except Exception` 抓不到它们——这是好事，否则你按 Ctrl+C 都停不下来。

## 7. ⚠️ 三个致命坑（新手常犯）

### 坑 1：裸 `except:`（不带任何异常类型）

```python
try:
    ...
except:              # ❌ 会把所有异常全吞掉，包括 Ctrl+C
    pass
```

> 后果：所有错误被无声吞掉，包括 `KeyboardInterrupt`，程序出问题你还找不到原因。

### 坑 2：`except Exception: pass`（"掩耳盗铃"）

```python
try:
    ...
except Exception:
    pass             # ❌ 错误被藏起来，后面出了怪 bug 根本查不到
```

> 至少要 `print` 或 `logging.exception()` 记录下来。

### 坑 3：大段代码全塞进 `try`

```python
try:
    # 100 行代码             # ❌ try 里的行数越多，掩盖的 bug 越多
    ...
except Exception:
    pass
```

> 正确做法：**只包住真正可能出错的那一行/那一个动作**。

## ⚠️ 易错点速记

1. `except` 顺序必须**子类在前、父类在后**
2. 自定义异常**必须继承 `Exception`**，否则 `raise` 直接报错
3. 别用裸 `except:`，它连 Ctrl+C 都吃
4. `except: pass` 是最危险的一行——错误被吞，bug 找不到
5. `finally` 无论如何都执行，适合放清理代码
6. `else` 是"没出错时执行"，不是"出错时执行"，别搞反
7. `try` 里**只放可能出错的那几行**，不要包一大段
