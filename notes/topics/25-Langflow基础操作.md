# Langflow 基础操作

> 一句话：Langflow 是**拖拽式**搭 AI 工作流的工具——**组件 = 积木，连线 = 数据流**。

## 1. 组件中文名速查（中文版界面）

| 用途 | 中文组件名 | 备注 |
| --- | --- | --- |
| 输入 | **聊天输入** | 输出端口叫「聊天消息」 |
| 输出 | **聊天记录** | ⚠️ 不是"聊天输出" |
| 大模型 | **语言模型** / **DeepSeek** | 二选一 |
| 提示词 | **提示模板** | |
| 智能体 | **代理程序** | 自带计算器、日期工具 |
| 计算器 | **计算器** | 在代理里是开关，不用单独拖 |
| 调试运行 | **Playground** | 这个词没翻译 |

## 2. 连线规则（记住就不会接错）

> **数据从左往右流**
> - **右侧**圆点 = 输出（数据出去）
> - **左侧**圆点 = 输入（数据进来）

```
聊天输入 ──聊天消息──► 语言模型「输入」
语言模型 ──语言模型──► 聊天记录「输入」
```

## 3. 三个入门练习

### 练习 1：最小对话回路

```
聊天输入 ──► 语言模型 ──► 聊天记录
```

配置：**语言模型** 里选 provider + model（红色星号是必填）。

### 练习 2：给它一个人设（提示模板）

```
聊天输入 ──► 提示模板 ──► 语言模型 ──► 聊天记录
```

- **提示模板** 里写人设，例如：
  ```
  你是一位耐心的 Python 老师。回答控制在三句话内，必须附一段代码示例。
  ```
- 提示模板的「提示」输出 → 语言模型的「**系统消息**」输入

**效果**：同一句话，回答风格完全变了 → 这就是**提示词工程**。

### 练习 3：让它会用工具（代理程序）

```
聊天输入 ──► 代理程序 ──► 聊天记录
```

**代理程序** 的关键字段：

| 字段 | 说明 |
| --- | --- |
| **语言模型**（红*） | 选 provider + model |
| **代理说明** | 系统提示，决定它怎么工作；支持 `{current_date}`、`{model_name}` 等占位符 |
| **工具** | 外部工具接入点 |
| **计算器** | 内置开关（安全：只支持 `+ - * / **`） |
| **当前日期** | 内置开关 |
| **处理解析错误** | 工具调用失败时自动重试（最多 2 次） |

**代理说明**示例：

```
你是一个严谨的数学助手。
遇到任何算术问题，必须调用计算器工具，绝对不要自己心算。
回答时先说明你用了什么工具，再给出结果。
```

**效果**：能看到它**先调工具 → 再组织答案**，这就是 Agent 的「思考→行动→观察」循环。

## 4. 记忆：默认就有，不用加组件

> Langflow 的 **语言模型** 和 **代理程序** 组件**内置了当前会话的聊天记忆，默认开启**。

| 需求 | 用什么 |
| --- | --- |
| 同一次对话里记得前文 | **不用加**，内置自带 |
| 关掉 Playground 后再开还能记得 | 加 **记忆库**（长期记忆） |

## 5. 常见报错与排查

### ① `Input data cannot be None`

**含义**：某个组件的必填输入是空的 → **连线没接上或接错端口**。

| 检查点 | 常见错误 |
| --- | --- |
| 聊天输入 → 模型 | 连到了「**系统消息**」而不是「**输入**」 |
| 模型 → 聊天记录 | 聊天记录的「输入」空着 |
| DeepSeek 组件的「输入」 | 必填，没连就报这个 |
| 「型号名称」 | 空着 |

**定位方法**：点每个组件标题栏的 ▶ 试运行，报错组件的**上游**就是问题点。

### ② 模型下拉是空的 / 红色星号还在

- 没选模型（红色星号 = 必填）
- 或 provider 配置没保存成功

### ③ Playground 里同一条消息显示两遍

这是**显示层面**的问题，AI 实际只回答一次。三个可能：

1. 画布上有**两个「聊天记录」组件**（每个都会显示一遍）
2. 「聊天输入」被直接连到了「聊天记录」（回显）
3. **会话历史累积**（之前发过同样的话）

**验证**：点 Playground 右上角「新会话/New Chat」清空后只发一次。

### ④ `Connector URL must be an http(s) URL...`

Base URL 框里填的是**变量名**（如 `OPENAI_COMPATIBLE_BASE_URL`）而不是真网址。
→ 改成 `https://api.deepseek.com`。

> 报错里提到的 `LANGFLOW_SSRF_ALLOWED_HOSTS` **只对内网地址**（如本地 Ollama）需要，公网域名不用管。

## 6. Langflow（拖拽）vs 写代码，怎么选

| | Langflow | 写代码 |
| --- | --- | --- |
| 上手 | 快，可视化 | 慢一点 |
| 复杂逻辑 | 难受 | 灵活 |
| 调试 | 看清每一步数据流 | 要自己打日志 |
| 面试价值 | 加分 | **核心** |

**建议**：用 Langflow 建立"直觉"，用代码（LangChain/LangGraph）建立"能力"。两者都学。

> ⚠️ 注意：Langflow 里**做不了**复杂的分支、循环、自定义状态机——那些必须回到代码。
> 所以 Langflow 适合"验证想法/演示"，真正的产品要写代码。

## ⚠️ 易错点速记

1. 右侧圆点是**输出**，左侧是**输入**，别接反
2. 「系统消息」是写人设的，**不是**对话输入端口
3. 「聊天记录」是输出组件的名字（不是"聊天输出"）
4. 红色星号 = 必填，没填就报错
5. Base URL 里**不要**手写变量名，也不要重复加 `/v1`
6. Playground 重复显示多为显示问题，不影响结果
