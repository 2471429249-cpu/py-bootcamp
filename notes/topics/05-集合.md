# 集合

> 一句话：set 是**无序、不重复**的容器；它的两大价值：**去重** 和 **快查（接近 O(1)）**。

## 1. 创建集合

```python
s = {1, 2, 3}          # 字面量创建
s = set([1, 2, 2, 3])  # 自动去重 → {1, 2, 3}

empty_set = set()      # ✅ 空 set
empty_dict = {}        # ❌ 这是空 dict！
```

> ⚠️ **易错点**：空集合不能用 `{}`——那会创建一个空字典。必须 `set()`。

## 2. 增删

```python
s = {1, 2, 3}
s.add(4)          # 添加
s.remove(2)       # 删除（元素不存在 → KeyError）
s.discard(99)     # 删除（元素不存在 → 静默通过，不报错）
```

> **remove 报错是保护机制**：如果代码认定"这个元素肯定在"，它却不在，说明前面的逻辑出错了。
> 报错能让你立刻发现问题；用 `discard` 会无声跑过去，最后得出错误结果反而难排查。

## 3. 集合运算

| 运算 | 符号 | 含义 |
| --- | --- | --- |
| 交集 | `a & b` | a 和 b 都有的元素 |
| 并集 | `a \| b` | a 和 b 任一有的元素（去重） |
| 差集 | `a - b` | a 有但 b 没有的元素 |
| 对称差 | `a ^ b` | 仅在 a 或仅在 b 中的元素 |

```python
a = {1, 2, 3}
b = {2, 3, 4}
a & b      # {2, 3}
a | b      # {1, 2, 3, 4}
a - b      # {1}
a ^ b      # {1, 4}
```

## 4. 什么时候用 set 而不是 list（性能）

```python
names_list = [f'user_{i}' for i in range(100000)]
names_set = set(names_list)

# 这两种结果一样，但是后者快得多
print('user_99999' in names_list)    # O(n)：元素越多越慢
print('user_99999' in names_set)     # 接近 O(1)：跟元素数量基本无关
```

> ⚠️ **结论**：大量「x in 集合」判断 → 先把 list 转 set。set 的价值不只是去重，更是**快查**。

## 5. set 的局限

- 无序：不能按索引访问 `s[0]` ❌
- 元素必须可哈希（list 不能放进 set）
- 想要"去重且保持原顺序"→ 用 `dict.fromkeys`（见 [07-去重与词频统计](07-去重与词频统计.md)）

## ⚠️ 易错点速记

1. `{}` 是空 dict，空 set 必须 `set()`
2. set 无序，不能索引、不能切片
3. 直接 `list(set(a))` 会丢原顺序
4. `in` 判断用 set 比 list 快得多（O(1) vs O(n)）
