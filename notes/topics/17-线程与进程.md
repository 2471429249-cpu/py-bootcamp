# 线程与进程

> 一句话：**IO 密集用线程（或异步），CPU 密集用多进程**——因为 CPython 有 GIL，多线程并不能让纯计算变快。

## 1. 先分清：进程 vs 线程

| | 进程（Process） | 线程（Thread） |
| --- | --- | --- |
| 是什么 | 一个独立运行的程序实例 | 进程里的执行单元 |
| 内存 | 各自独立，互不共享 | **共享**同一进程内存 |
| 开销 | 创建/切换贵 | 轻量、快 |
| 通信 | 要队列/管道/共享内存 | 直接读写同一变量（**但要加锁**） |
| 受 GIL 限制 | ❌ 不受 | ✅ 受 |

> **GIL（全局解释器锁）**：CPython 里同一时刻只允许一个线程执行 Python 字节码。
> 所以多线程**不能让纯计算变快**，只能让"等 IO"的时间重叠起来。

## 2. 创建线程：`threading.Thread`

```python
import threading
import time


def worker(name, count=1):
    for i in range(count):
        print(f"{name}: {i}")
        time.sleep(0.5)


if __name__ == "__main__":
    # args：以元组的方式给执行任务传递参数
    t1 = threading.Thread(target=worker, args=("A", 3), name="线程A")
    # kwargs：以字典方式给执行任务传递参数
    t2 = threading.Thread(target=worker, kwargs={"name": "B", "count": 2}, name="线程B")

    t1.start()          # 启动（真正开始跑）
    t2.start()
    t1.join()           # 等 t1 结束
    t2.join()
    print("全部完成")
```

**参数速查**

| 参数 | 说明 |
| --- | --- |
| `target` | 要执行的函数（**不要加括号**，是函数对象） |
| `args` | 位置参数元组，单元素要写 `(3,)`，**末尾逗号不能省** |
| `kwargs` | 关键字参数字典，如 `{"count": 2}` |
| `name` | 线程名（调试/日志用） |
| `daemon` | `True` = 主线程结束就跟着被杀（后台线程） |

> ⚠️ `target=worker()` 会在创建时就执行，并把**返回值**当 target → 错。
> 正确写法是 `target=worker`。

## 3. `start` / `join` / `daemon`

```python
t = threading.Thread(target=worker, daemon=True)
t.start()
# 主线程结束时，daemon 线程会被直接杀掉，不会等它跑完
```

```python
t.start()
t.join(timeout=2)      # 最多等 2 秒；超时就不等了
```

## 4. 线程安全：`Lock`

多个线程**同时修改**同一个变量会出问题（`counter += 1` 不是原子操作）：

```python
import threading

lock = threading.Lock()
counter = 0


def add():
    global counter
    for _ in range(100_000):
        with lock:          # 加锁，保护临界区
            counter += 1


ts = [threading.Thread(target=add) for _ in range(4)]
for t in ts: t.start()
for t in ts: t.join()
print(counter)              # 400000（不加锁通常小于这个数）
```

- `Lock`：普通锁，**不可重入**（同一线程重复 acquire 会死锁）
- `RLock`：可重入锁，同一线程可以多次 acquire
- `with lock:` 是标准写法（自动释放）

## 5. `Condition`：等一个条件成立（生产者/消费者）

`Condition` = 锁 + 等待/通知机制。典型用途：**没有数据就等，有数据就唤醒**。

```python
import threading
import time

cond = threading.Condition()
items = []


def producer():
    for i in range(5):
        with cond:
            items.append(i)
            print(f"生产 {i}，当前队列 {items}")
            cond.notify()           # 唤醒一个正在 wait 的线程
        time.sleep(0.3)


def consumer():
    for _ in range(5):
        with cond:
            while not items:        # 必须用 while，不能用 if（防虚假唤醒）
                cond.wait()         # 等待时会【自动释放锁】，被唤醒后重新拿锁
            item = items.pop(0)
            print(f"消费 {item}")


t1 = threading.Thread(target=producer)
t2 = threading.Thread(target=consumer)
t1.start(); t2.start()
t1.join(); t2.join()
```

**关键点**

| 方法 | 作用 |
| --- | --- |
| `cond.wait()` | 释放锁并阻塞，直到被 `notify` 唤醒（醒来后重新拿锁） |
| `cond.notify()` | 唤醒**一个**等待者 |
| `cond.notify_all()` | 唤醒**所有**等待者 |
| 用 `with cond:` | 进出自动 加锁/解锁 |

> ⚠️ 判断条件必须用 `while` 而不是 `if`——被唤醒后条件可能又被别的线程改回去了。

## 6. `Queue`：最省心的线程间通信

不要自己用 list + 锁，直接用 `queue.Queue`（**本身线程安全**）：

```python
import queue
import threading

q = queue.Queue(maxsize=10)     # 有界队列，满了 put 会阻塞


def producer():
    for i in range(5):
        q.put(i)


def consumer():
    while True:
        item = q.get()
        print("处理", item)
        q.task_done()           # 告诉队列这项处理完了


t1 = threading.Thread(target=producer)
t2 = threading.Thread(target=consumer, daemon=True)
t1.start(); t2.start()
q.join()                        # 等所有任务被 task_done
```

三种队列：`Queue`（FIFO）、`LifoQueue`（栈）、`PriorityQueue`（优先级）。

## 7. 实战最常用：线程池 `ThreadPoolExecutor`

**不用手动建线程**，交给池子（爬虫、批量请求、批量文件处理都用它）：

```python
from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    # 模拟网络请求
    return f"{url} 的结果"

urls = [f"https://example.com/{i}" for i in range(10)]

with ThreadPoolExecutor(max_workers=8) as pool:
    results = list(pool.map(fetch, urls))     # 顺序与 urls 一致

print(results)
```

也可以用 `submit` + `as_completed`（谁先完成先处理）：

```python
from concurrent.futures import as_completed

with ThreadPoolExecutor(max_workers=8) as pool:
    futures = [pool.submit(fetch, u) for u in urls]
    for f in as_completed(futures):
        print(f.result())
```

## 8. 多进程：绕开 GIL 跑满 CPU

```python
from multiprocessing import Pool


def cpu_heavy(n):
    return sum(i * i for i in range(n))


if __name__ == "__main__":       # Windows 上必须放在 __main__ 里！
    with Pool() as p:
        print(p.map(cpu_heavy, [10**6] * 4))
```

> ⚠️ Windows 用的是 `spawn` 方式，**多进程代码必须写在 `if __name__ == "__main__":` 下面**，否则会无限递归。

## 9. `threading.Event`：线程间发信号（优雅退出）

线程**不能强制 kill**，用 Event 通知它自己退出：

```python
import threading, time

stop_event = threading.Event()


def loop_task():
    while not stop_event.is_set():
        print("工作中...")
        time.sleep(0.5)
    print("收到停止信号，退出")


t = threading.Thread(target=loop_task)
t.start()
time.sleep(2)
stop_event.set()          # 发信号
t.join()
```

## 10. 怎么选：一张决策表

| 场景 | 选什么 | 原因 |
| --- | --- | --- |
| 网络请求、读写文件、数据库（**IO 密集**） | 多线程 / 线程池 / asyncio | 等 IO 时切换，能重叠等待 |
| 大量数学计算、图像处理（**CPU 密集**） | 多进程 | 绕开 GIL，真正并行 |
| 需要共享大量数据、逻辑简单 | 多线程 + Lock/Queue | 共享内存方便 |
| 任务数量固定、要拿结果 | `ThreadPoolExecutor` / `Pool` | 池化，省去手写线程管理 |
| 超多并发连接（几千） | `asyncio` | 协程比线程轻得多 |

## ⚠️ 易错点速记

1. `target=worker()` 错！**不加括号**，传函数对象
2. `args=(3,)` 单元素元组，**逗号不能省**，否则是整数
3. 共享变量 += 要加 `Lock`，否则结果偏小
4. `Condition.wait()` 外面必须用 **`while`** 判断条件，不能用 `if`
5. Windows 多进程代码必须放在 `if __name__ == "__main__":` 下
6. 线程不能强杀，用 `Event` 通知退出
7. 线程间通信优先用 `queue.Queue`，别自己拿 list 加锁
8. 纯计算任务用多线程**不会变快**（GIL），要用多进程
